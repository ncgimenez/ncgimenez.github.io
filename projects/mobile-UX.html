SNCB: Know Which Way to Run Before You Get There

Rethinking transit mobile notifications for high-friction connections. Surfacing real-time arrival platforms and train exit door directions before reaching connecting hubs.

App Context
SNCB / NMBS Official Mobile App
Focus
Spatial Awareness & Friction Reduction
Role
Product & Interaction Designer
Target Metric
Connection Miss Rate Reduction

The Commuter's High-Stress Moment

In Belgian rail transit, a 4-minute connection between regional IC trains at Brussels-Midi or Liège-Guillemins is not rare. Commuters stand in crowded aisles, waiting for the train to halt before opening the official app to discover two things:

  • Which platform their connecting train is departing from.
  • Whether they need to take the stairs up, down, or navigate an underpass.

Default transit apps present this information as a static list of stops. They require 3 taps to view platform details while juggling luggage, coats, and cell signal drops in tunnels.

Core Interaction Hypothesis: Information is only useful if delivered at the moment of highest leverage. Displaying platform updates 3 minutes before arrival—coupled with exit side orientation—converts blind panic into prepared navigation.

The Interface Solution: Pre-Arrival Dynamic Island & Notification

Key Architectural Decisions

  • Pre-emptive Arrival Trigger: Push critical transfer data based on GPS / geo-fencing 3 minutes prior to arrival, bypassing spotty station Wi-Fi.
  • Physical Car Orientation: Stating the train door release side (Left or Right) prevents commuters from queuing at the wrong side of crowded vestibules.
  • Walk-Time Calibrated Feasibility: If a delay shrinks the connection time below the physical distance threshold between tracks, the interface immediately offers the next viable fallback connection rather than leaving passengers to run toward a closed departure.
