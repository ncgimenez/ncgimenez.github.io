The Span Suite: Planning Without Overwhelm, Executing Without Clutter

A dual-engine productivity ecosystem closing the gap between macro scheduling and single-task execution. Built with React, Supabase, and tactile offline-first interactions.

1. The Problem: Without Structure, To-Do Lists Are Overwhelming

Most productivity tools fail because they treat human attention as infinite. They act as passive endless inventories: you dump forty items into a column, stare at the backlog every time you open the app, and carry a subconscious debt throughout the day.

Core Insight: Without an opinionated frame, every to-do list collapses into cognitive backlog debt. Real productivity does not happen by adding checkmarks; it happens by defending boundaries.

Coming from an ERP and enterprise systems background, I observed the exact same dynamic: an organization cannot promise a customer delivery without first reserving warehouse capacity (Available-to-Promise). The human mind functions identically: you cannot execute a task without explicitly reserving mental bandwidth and dedicated temporal real estate for it.

Engine 01 · Macro

Span Plan

The Structuring Frame

Where intentions become commitments. A calendar-aware space where tasks are slotted into concrete timeframes (Today, Tomorrow, Later), preventing the cognitive exhaustion of a bottomless backlog.

  • Automated Rollover: Incomplete tasks gracefully slide to the next planning window without guilt-inducing alarms.
  • Contextual Categories: Strict division across Work, Life, and Focus to maintain visibility over energy balance.
  • Selective Focus Feeder: Promotes only top-tier daily priorities into the execution chamber.
Engine 02 · Micro

Span Focus

The Execution Chamber

A hermetic, distraction-free environment designed for single-task immersion. The backlog is deliberately hidden; only the current sprint matters.

  • 25-Minute Block Timer: Calibrated Pomodoro-style sprints with real-time target feedback and completion metrics.
  • Keyboard & Gesture Native: Swipe right to trigger focus, Enter to complete, Tab to edit, long-press to star. Zero mouse dependency.
  • Daily Goal Tracking: Real-time progress bar reflecting actual dedicated time against daily intentions.

3. Tactile Interaction & Mobile-First Ergonomics

Software quality lives in micro-interactions and predictability under constrained mobile viewports. Throughout the Span suite, several non-negotiable principles guided the design:

  • Keyboard-First Ergonomics: Switching between mouse and keyboard causes mental drag. In Span Focus, every frequent action can be operated entirely from the home row.
  • Mobile Thumb-Zone Calibration: Primary execution triggers are positioned within natural thumb sweep areas on mobile devices, avoiding unreachable upper corners.
  • iOS Viewport Resilience: Handled dynamic mobile browser address bar resizes via modern CSS viewport units (100dvh) to keep action trays fixed without layout jump.
  • Dark-Mode Slate Palette: Productivity tools are frequently used during early morning or late-night focus sessions. The palette avoids harsh stark contrast in favor of an eye-resting dark slate workshop aesthetic.

4. Engineering Trade-offs & Post-Mortems

Building production tools means navigating real-world constraints. Here are three architectural challenges encountered during development and how they were resolved:

Challenge Initial Friction / Failure Mode Engineered Resolution
Midnight Rollover Unfinished tasks accumulated as visual red marks on past days, creating backlog fatigue and artificial urgency. Engineered an automated rollover state machine that gracefully reschedules incomplete tasks into the active day buffer without penalty.
Offline Resilience Unstable mobile connections (e.g. transit commutes) risked dropped sessions when relying purely on direct cloud calls. Implemented an offline-first architecture: local storage / IndexedDB acts as the primary synchronous source of truth, with asynchronous background sync to Supabase.
State Overhead Complex state management libraries introduced noticeable bundle weight and boot latency on mobile devices. Maintained a lightweight, deterministic component state pipeline, keeping initial boot times below 200ms on mobile viewports.

I build these applications using modern AI workflows as force multipliers. This process is not passive copy-pasting; it is an active discipline of functional orchestration:

Systems Thinking Applied to Code: LLMs provide raw syntax velocity, but they lack product vision and systemic taste.
