Google Calendar: Rethinking the Interaction Model

Drag to select, click to create: bringing standard desktop marquee selection and batch manipulation to temporal schedule changes.

Application
Calendar Scheduling (Web/Desktop)
Focus
Interaction Primitives & Ergonomics
Role
Interaction Designer
Core Hypothesis
Batch drag reduces rescheduling fatigue

The Conflict of Interaction Paradigms

In modern desktop software, clicking and dragging on empty canvas space universally triggers a marquee bounding box to select multiple entities. You see this in Figma, operating system desktops, spreadsheet cell ranges, and digital audio workstations.

Google Calendar violates this expectation. Clicking and dragging on empty calendar space creates an immediate, blank tentative meeting. To move four adjacent meetings back by 30 minutes, users must perform four discrete drag-and-drop operations, frequently misaligning event durations or triggering unwanted notification modals.

The Friction Point: Rescheduling a fragmented afternoon requires repetitive, granular adjustments instead of a single, fluid selection gesture.

Proposed Interaction Architecture

Separating creation from selection via contextual modifier keys and standard desktop spatial gestures:

  end

Core Interaction Upgrades

  • Marquee Multi-Select: Dragging across empty background grid selects all overlapping event nodes simultaneously, displaying a unified boundary.
  • Atomic Block Shifting: Moving the selection maintains relative offsets between events, preserving planned break intervals automatically.
  • Single-Click Creation Anchor: A simple click-and-release creates an event with smart default duration, freeing click-and-drag for spatial framing.
